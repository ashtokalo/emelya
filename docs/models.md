# Модели и роутинг

## Обзор

Emelya поддерживает несколько LLM-моделей одновременно через конфигурацию `models.json`.
Модели можно переключать вручную (`/model <name>`) или настроить автоматический роутинг
с failover-цепочками для разных типов задач.

---

## Конфигурационный файл

Файл `models.json` — JSON-объект с двумя ключами:

```json
{
  "models": {
    "имя_модели": { /* настройки */ }
  },
  "routing": {
    "операция": ["модель1", "модель2"]
  }
}
```

### Поля модели

| Поле | Тип | Обязательное | Описание |
|------|-----|-------------|----------|
| `base_url` | string | да | Базовый URL API (без `/v1/...`) |
| `model` | string | да | Идентификатор модели |
| `api_key` | string | нет | API-ключ (Bearer token). Файл получает права `0600` при сохранении |
| `context_limit` | integer | нет | Лимит токенов контекста. Если не задан — автоопределение или 4096 |
| `max_tokens` | integer | нет | Максимум токенов в ответе. Default: 8192 |
| `proxy` | string | нет | Прокси для этой модели: URL (`socks5://...`) или имя из `proxies` |

### Поддерживаемые провайдеры

| Провайдер | `base_url` | Автодетект контекста |
|-----------|-----------|---------------------|
| Локальный llama.cpp | `http://localhost:8080` | через `/props` (n_ctx) |
| OpenAI | `https://api.openai.com` | 128 000 |
| DeepSeek | `https://api.deepseek.com` | 128 000 |
| OpenRouter | `https://openrouter.ai/api` | 128 000 |
| Любой OpenAI-совместимый | любой URL | — |

### Пример

```json
{
  "proxies": {
    "vpn": "socks5://user:pass@proxy.example.com:1080"
  },
  "models": {
    "gpt4": {
      "base_url": "https://api.openai.com",
      "model": "gpt-4o",
      "api_key": "sk-...",
      "context_limit": 128000,
      "proxy": "vpn"
    },
    "deepseek": {
      "base_url": "https://api.deepseek.com",
      "model": "deepseek-chat",
      "api_key": "sk-...",
      "max_tokens": 8192
    },
    "local-big": {
      "base_url": "http://localhost:8080",
      "model": "default",
      "context_limit": 32768
    }
  }
}
```

---

## Встроенная модель `local`

Модель `local` создаётся автоматически из аргументов запуска:

```bash
emelya --base-url http://localhost:8080 --model mymodel
```

Переопределить её через `models.json` нельзя — она всегда отражает текущие параметры CLI.

---

## Глобальная и локальная конфигурация

Файлы загружаются в следующем порядке:

```
~/.emelya/models.json     ← глобальный (пользовательский)
.emelya/models.json       ← локальный (проектный)
```

Слияние: `dict.update()` — локальные записи перекрывают глобальные для совпадающих
имён моделей и операций роутинга. Это касается как `models`, так и `routing`.

**Пример:** если глобально задана модель `gpt4`, а локально — тоже `gpt4`, но с другим
`api_key`, то для проекта будет использоваться локальная версия.

## Роутинг

Роутинг позволяет автоматически выбирать модель для разных операций.
Если модель в начале цепочки недоступна — происходит автоматический переход к следующей.

### Операции роутинга

| Операция | Когда используется |
|----------|-------------------|
| `default` | Основной диалог с пользователем |
| `agent` | Субагенты с write-инструментами |
| `agent_light` | Субагенты только с read-инструментами (glob, grep, read) |
| `planner` | Субагент-планировщик |

### Формат

```json
{
  "routing": {
    "default": ["deepseek", "gpt4"],
    "agent_light": ["local-big", "deepseek"],
    "agent": ["gpt4"],
    "planner": ["gpt4"]
  }
}
```

Операции из `routing` разрешаются последовательно:
1. Берётся первая модель из цепочки
2. Проверяется доступность (`/v1/models` или аналог)
3. Если доступна — отправляется запрос
4. При ошибке — следующая модель в цепочке

Если операция не задана явно — используется цепочка `default`.

### Автоклассификация субагентов

Тип роутинга для субагентов определяется автоматически по набору tools в `.md`-файле агента:
- Только read-only tools (`read`, `glob`, `grep`) → `agent_light`
- Есть write-tools → `agent`
- Агент с именем `planner` → `planner`

## Прокси

### Прокси для модели

Каждой модели можно назначить прокси через поле `proxy`. Значение — либо прямой URL,
либо имя из секции `proxies` (удобно, когда несколько моделей используют один прокси).

```json
{
  "proxies": {
    "vpn": "socks5://user:pass@proxy.example.com:1080"
  },
  "models": {
    "openai": {
      "proxy": "vpn"
    },
    "other": {
      "proxy": "http://corp-proxy:8080"
    }
  }
}
```

### Поддерживаемые схемы прокси

| Схема | Описание |
|-------|----------|
| `http://[user:pass@]host:port` | HTTP CONNECT прокси |
| `socks5://[user:pass@]host:port` | SOCKS5, резолвинг через прокси |
| `socks5h://[user:pass@]host:port` | То же, что `socks5://` — резолвинг всегда на стороне прокси |

Реализация SOCKS5 встроена, внешние зависимости не требуются.

### Переменные окружения

Если у модели не задан `proxy`, применяются переменные окружения (в порядке приоритета):

| Переменная | Описание |
|------------|----------|
| `HTTPS_PROXY` / `https_proxy` | Прокси для HTTPS-соединений |
| `ALL_PROXY` / `all_proxy` | Универсальный прокси (поддерживает `socks5://`) |
| `HTTP_PROXY` / `http_proxy` | Прокси для HTTP-соединений |

Переменная окружения применяется ко всем моделям без явного `proxy`.
Явный `proxy` в конфиге модели всегда имеет приоритет над переменными окружения.

```bash
# Пустить весь трафик через SOCKS5
ALL_PROXY=socks5://proxy.example.com:1080 emelya

# HTTP-прокси для всех моделей без явного proxy
HTTPS_PROXY=http://corp-proxy:8080 emelya
```

## Команды `/model`

```
/model                     — показать список моделей и текущий статус роутинга
/model <name>              — переключиться на модель (отключает роутинг)
/model auto                — включить роутинг обратно
/model add <name> <url> <model> [api_key] [--context-limit N]
                           — добавить модель и сохранить в .emelya/models.json
/model remove <name>       — удалить модель
```

### Примеры

```
/model add deepseek https://api.deepseek.com deepseek-chat sk-xxx
/model add gpt4 https://api.openai.com gpt-4o sk-xxx --context-limit 128000
/model add local8k http://localhost:8080 default --context-limit 8000
/model deepseek
/model auto
```

При добавлении модели (`/model add`) проверяется соединение и сохраняется в
`.emelya/models.json` текущего проекта. API-ключи не попадают в глобальный файл
(они остаются в проектном `.emelya/models.json` с правами `0600`).

---

## Ручное управление vs роутинг

| Режим | Как активировать | Поведение |
|-------|-----------------|-----------|
| Роутинг (auto) | `/model auto` или по умолчанию | Выбирает модель автоматически по операции |
| Ручной | `/model <name>` | Всегда использует указанную модель |

В ручном режиме в строке статуса отображается имя активной модели.
В режиме роутинга отображается та модель, которая ответила последней.
