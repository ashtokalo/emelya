# Система навыков (Skills)

## Концепция

Навык — это .md файл с инструкциями, которые модель может загрузить в контекст,
когда ей нужны специализированные знания. Навыки не занимают контекст до загрузки.

Модель вызывает tool `skill(name="git")` → содержимое `skills/git.md`
возвращается как tool result → модель получает инструкции и использует их.

## Каталоги навыков

Навыки загружаются из трёх источников в следующем порядке приоритета:

```
встроенные  <app>/skills/        — стандартные навыки (поставляются вместе с emelya)
глобальные  ~/.emelya/skills/    — пользовательские навыки для всех проектов
локальные   .emelya/skills/      — навыки конкретного проекта
```

Если навык с одним именем присутствует в нескольких каталогах — используется
вариант с наибольшим приоритетом (локальный > глобальный > встроенный).

### Встроенные навыки

```
<app>/skills/
├── python.md        — Python (venv, pip, pytest, ruff)
├── javascript.md    — Node.js (npm, jest, eslint)
├── php.md           — PHP (Composer, Laravel, phpunit)
├── go.md            — Go (modules, build, test, vet)
├── c_cpp.md         — C/C++ (gcc, make/cmake, gdb, valgrind)
├── rust.md          — Rust (cargo, clippy, fmt)
├── git.md           — Git workflows
├── docker.md        — Docker и docker-compose
├── makefile.md      — Makefiles
├── bash_scripting.md — Safe bash scripts (shellcheck)
├── html.md          — HTML validation, preview
├── css.md           — CSS debugging, responsive
├── data.md          — JSON, YAML, CSV
├── design.md        — SOLID, patterns, code smells
└── project.md       — README, CHANGELOG, LICENSE, CI
```

### Пользовательские навыки

Создайте `.md`-файл в `~/.emelya/skills/` или `.emelya/skills/`:

```bash
mkdir -p ~/.emelya/skills
cat > ~/.emelya/skills/myframework.md << 'EOF'
---
description: Работа с MyFramework
---
# MyFramework

Инструкции для работы с MyFramework...
EOF
```

После этого навык `myframework` будет доступен во всех проектах через
`skill(name="myframework")` или `/skill myframework`.

Чтобы переопределить встроенный навык `git` — создайте файл с тем же именем
в `~/.emelya/skills/git.md` или `.emelya/skills/git.md`.

## Формат файла навыка

```markdown
---
description: Работа с git репозиториями
---
# Git

Инструкции для работы с git.

## Просмотр состояния

Используй bash для выполнения git команд:
- `git status` — текущее состояние
- `git log --oneline -20` — последние коммиты
- `git diff` — незафиксированные изменения

## Создание коммита

1. Посмотри изменения: `git diff --staged`
2. Если ничего не добавлено: `git add <файлы>`
3. Создай коммит: `git commit -m "описание"`
...
```

### Frontmatter

| Поле | Обязательное | Описание |
|------|-------------|----------|
| `description` | да | Краткое описание навыка (одна строка). Показывается модели в списке доступных навыков |

### Тело

Markdown-текст с инструкциями для модели. Может содержать:
- Пошаговые инструкции
- Примеры команд
- Предупреждения и ограничения
- Ссылки на дополнительные навыки

## Жизненный цикл

### 1. Сканирование при запуске

При старте агента сканируются все три каталога в порядке приоритета:
встроенный → глобальный → локальный.
Навыки с одинаковым именем: локальный перекрывает глобальный, глобальный — встроенный.

- Из каждого .md файла читается frontmatter (только `description`)
- Формируется список для tool definition `skill`:

```
"description": "Load a skill. Available: git (Работа с git), data (JSON, YAML, XML), python (Python разработка)"
```

Тела файлов НЕ читаются и НЕ загружаются в контекст.

### 2. Загрузка по запросу модели

Модель вызывает `skill(name="git")`:
1. Читается файл `skills/git.md`
2. Парсится frontmatter, извлекается тело
3. Тело возвращается как tool result
4. Навык помечается как загруженный (в множестве `loaded_skills`)

### 3. Повторный запрос

Если модель вызывает `skill(name="git")` повторно:
- Возвращается `"Skill 'git' is already loaded"` (без повторной загрузки)

### 4. Очистка

При `/clear` — множество `loaded_skills` очищается.
При `/compact` — навыки сохраняются (не сжимаются вместе с историей).

## Взаимодействие с контекстом

Загруженный навык — это обычный tool result в истории сообщений:

```json
[
  {"role": "assistant", "tool_calls": [
    {"id": "call_1", "function": {"name": "skill", "arguments": "{\"name\": \"git\"}"}}
  ]},
  {"role": "tool", "tool_call_id": "call_1", "content": "# Git\n\nИнструкции для работы с git.\n..."}
]
```

Он остаётся в контексте как любое другое сообщение и может быть удалён
при trimming (если контекст переполнен).

## Рекомендации по написанию навыков

### Размер

Оптимально: 300-800 токенов (~150-400 слов). Это балансирует между
полнотой инструкций и расходом контекста. Для модели с 8K контекстом
один навык не должен занимать более 10% контекста.

### Содержание

- Конкретные примеры команд (через bash tool)
- Порядок действий (пронумерованные шаги)
- Предупреждения о типичных ошибках
- НЕ дублировать то, что модель знает из обучения (синтаксис языка, базовые команды)
- Фокус на специфике проекта и рабочем процессе

### Гранулярность

Один навык — одна предметная область. Не нужно объединять git + docker + kubernetes
в один файл "devops.md". Модель загрузит только то, что нужно.

Но и не нужно дробить слишком мелко: "git-commit.md", "git-branch.md", "git-merge.md".
Одного "git.md" достаточно.

## Отличие от субагентов

| | Навык (Skill) | Субагент (Agent) |
|---|---|---|
| Что происходит | Текст добавляется в текущий контекст | Запускается отдельный цикл inference |
| Контекст | Общий с основным диалогом | Изолированный |
| Tools | Все tools основного агента | Ограниченный набор |
| Результат | Модель продолжает диалог с новыми знаниями | Возвращается строка-результат |
| Когда использовать | Нужны инструкции "как делать" | Нужно выполнить конкретную задачу |
